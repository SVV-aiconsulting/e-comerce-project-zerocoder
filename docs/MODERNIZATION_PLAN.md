# План модернизации WebMarket для выпускного проекта

Статус: утверждён, выполняется  
Дата фиксации: 24.08.2026

## 1. Цель модернизации

Преобразовать существующий WebMarket в омниканальную AI-систему, которая принимает
неструктурированные заявки, понимает естественный язык, уточняет недостающие данные,
автоматически создаёт заказ в PostgreSQL CRM и ведёт его до доставки и оплаты.

Существующие каталог, клиенты, корзины, заказы, скидки, Django Admin, Telegram- и
VK-адаптеры сохраняются как основа проекта.

## 2. Зафиксированный уровень внедрения LLM

Принято решение реализовать **управляемого AI-ассистента продаж**, а не автономного
агента с прямым доступом к CRM.

LLM используется для:

- определения намерения клиента;
- извлечения товаров, количества, адреса, даты, времени и комментария;
- понимания контекста и исправлений в диалоге;
- определения неоднозначных и отсутствующих данных;
- формулирования уточняющих вопросов и естественных ответов;
- безопасных рекомендаций на основании фактического каталога.

Детерминированный Python-код используется для:

- идентификации и авторизации клиента;
- поиска фактических товаров и проверки наличия;
- проверки количества и единиц измерения;
- расчёта цен, скидок и итоговой суммы;
- вызова API доставки;
- транзакционного создания заказа;
- создания платёжной ссылки;
- проверки webhook и изменения платёжного статуса;
- формирования и хранения данных счёта и чека.

### Архитектурные ограничения

- LLM не получает произвольный SQL и прямой доступ к Django ORM.
- LLM не назначает цену и не подтверждает наличие товара.
- LLM не создаёт заказ и платёж до явного подтверждения клиента.
- Любой structured output проходит серверную валидацию.
- Внешние события и операции записи должны быть идемпотентными.
- Ошибки и низкая уверенность приводят к уточнению или передаче менеджеру.

### Решение по фреймворку

Первый рабочий AI-MVP создаётся без полноценного LangChain/Haystack Agent:

- прямой SDK выбранного LLM-провайдера;
- строгий structured output;
- `OrderDraft` в PostgreSQL;
- управляемая state machine в сервисном слое.

LangGraph допускается как второй уровень после стабилизации MVP, если потребуется
наглядная оркестрация долгого диалога, pause/resume и human-in-the-loop. Haystack
не включается в базовый scope: для структурированного каталога достаточно Django ORM,
поиска по синонимам и, при необходимости, PostgreSQL trigram/pgvector.

## 3. Целевой data flow

```text
Telegram / VK / Email / Web
              |
              v
      единый InboundEvent
              |
              v
       очередь Celery/Redis
              |
              v
     LLM -> OrderIntent (JSON)
              |
              v
    каталог + server validation
              |
       +------+------+
       |             |
  нужны данные     всё готово
       |             |
  уточнение       OrderDraft
       |             |
       +------> подтверждение клиента
                         |
                         v
              существующий OrderService
                         |
                  расчёт доставки
                         |
                  платёжная ссылка
                         |
                   webhook оплаты
                         |
                   CRM + Dashboard
```

## 5. Приоритеты

### Must have

- естественный язык минимум в Telegram, email и web;
- единая очередь;
- `OrderDraft`, валидация и уточняющие вопросы;
- автоматическое создание заказа после подтверждения;
- интеграция Яндекс Доставки;
- sandbox-оплата и webhook;
- CRM/dashboard и библиотека промптов;
- тесты и VPS deployment.

### Should have

- VK как дополнительный полноценный AI-канал;
- рекомендации аналогов;
- передача сложного случая менеджеру;
- аналитика качества AI.

### Could have

- MAX;
- LangGraph-визуализация workflow;
- semantic search/pgvector;
- повтор прошлого заказа и персональные рекомендации.

## 6. Метрики результата

- доля заказов, оформленных без менеджера;
- точность сопоставления товаров и количества;
- доля диалогов с уточнениями;
- среднее число сообщений до подтверждения;
- доля передачи менеджеру;
- средняя стоимость и задержка LLM на заказ;
- число дубликатов заказов и платежей (целевое значение — 0);
- успешность webhook и доставки.
