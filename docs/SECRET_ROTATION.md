# Регламент ротации секретов WebMarket

Версия: 1.0
Дата: 07.09.2026
Статус: подготовлен; фактическая ротация требует действий владельца

## Назначение

Ротация выполняется согласованно между внешним сервисом, GitHub Actions и `.env` на
VPS. Значения секретов нельзя коммитить, выводить в команды диагностики или
пересылать в библиотеку промптов. Перед началом создаётся проверенный backup БД и
фиксируется SHA текущего рабочего релиза.

## Инвентаризация и порядок

| Группа | Где обновить | Безопасная последовательность | Проверка |
|---|---|---|---|
| `DJANGO_SECRET_KEY` | `.env` VPS | создать стойкое значение, заменить и перезапустить `web`/workers/bots | health, admin; старые web-сессии будут завершены |
| PostgreSQL password | роль PostgreSQL и `.env` VPS | backup → сменить пароль роли → синхронно обновить `.env` → перезапустить сервисы | health, миграции, чтение CRM |
| `ADAPTER_API_TOKENS` | backend и `.env` адаптеров | временно разрешить новый токен вместе со старым → обновить адаптеры → удалить старый | Telegram/VK/API smoke |
| Telegram/VK tokens | кабинеты платформ и `.env` VPS | выпустить/отозвать в кабинете → обновить `.env` → перезапустить только соответствующий bot | `/start`, health бота |
| GigaChat credentials | кабинет провайдера и `.env` VPS | выпустить новое значение → заменить → перезапустить workers/web | один безопасный каталожный запрос |
| ЮKassa secret | кабинет магазина и `.env` VPS | для test и production отдельно; заменить, затем проверить read-only API и тестовый платёж | payment + webhook |
| Яндекс Почта | пароль приложения и `.env` VPS | выпустить новый пароль приложения → заменить → перезапустить email worker → отозвать старый | IMAP intake + SMTP reply |
| SSH deploy key | VPS `authorized_keys` и GitHub Secret `VPS_SSH_KEY` | добавить новый public key → обновить GitHub Secret → успешный deploy → удалить старый key | Actions deploy + HTTPS health |

Публичный GHCR не требует `VPS_GHCR_TOKEN`; отсутствующий секрет не нужно создавать
только ради регламента.

## Выполнение одного окна ротации

1. Выбрать один тип секрета и окно с возможностью отката.
2. Сделать backup и записать только название секрета, дату и ответственного — без
   старого или нового значения.
3. Выпустить новое значение в источнике, если сервис допускает перекрытие ключей.
4. Обновить GitHub Secret или `.env` VPS через защищённый канал.
5. Перезапустить минимальный набор контейнеров.
6. Выполнить проверку из таблицы и просмотреть логи на отсутствие значения секрета.
7. Отозвать старое значение только после успешной проверки нового.
8. При ошибке вернуть предыдущее значение, восстановить сервис и оформить инцидент.

## Критерий завершения пункта плана

Пункт «Ротация секретов» можно отметить выполненным только после фактической смены
минимум `DJANGO_SECRET_KEY`, пароля PostgreSQL, adapter tokens и deploy SSH key на
VPS, успешного CI/CD deployment и smoke-тестов. Подготовка этого документа сама по
себе ротацией не является.
